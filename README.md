# LLMBatDesk 1.3.4

LLMBatDesk 是一个使用 PySide6 / Qt Widgets、以简体中文为默认界面的 Windows 桌面管理器，用来扫描、理解、整理并运行用户现有的 `.bat` / `.cmd` 本地 LLM 启动脚本。脚本始终是技术参数的唯一事实来源；数据库只保存显示名、收藏、标签、游戏、用途、笔记、排序、信任哈希及运行历史。

运行路径保持为：

```text
游戏模组 -> Ollama 或 llama.cpp
```

LLMBatDesk 不代理请求、不读取流式 token、不加载 GGUF，也不会在退出后影响生成速度。

1.3.x 包含默认关闭的内置“模型库”。它只提供本地 GGUF 的手动只读索引和脚本引用信息，
不参与启动必需流程，也不位于客户端与 llama.cpp/Ollama 之间。

## 功能

- 多根目录递归扫描、单文件添加、排除目录、规范路径去重、5 秒低频自动变更检测。
- 解析 UTF-8、GB18030、CP932、UTF-16（带 BOM）和常见西文编码；支持中文和空格路径。
- 支持 `^` 续行、静态 `set`、`%VAR%` 展开、注释，并检测 `CALL`、`START`、标签/`GOTO`、`set /p`、延迟展开、重定向和引号错误。
- llama.cpp：模型、主机、端口、上下文、GPU 层、批量、线程、缓存、采样、Jinja、模板、草稿模型、API key 状态及未知参数。
- Ollama：`serve`、`run`、`stop` 及常见 `OLLAMA_*` / GPU 环境变量。
- 未知后端保持可启动，并明确显示为通用/部分解析。
- 现代 Qt 暗色三栏界面，可即时切换浅色主题；窗口、三块面板和内容型对话框均可调整大小。
- 记忆窗口尺寸/位置、最大化状态和面板分隔位置；详情使用分组卡片和独立原文/证据查看器。
- Per-Monitor-V2 DPI 感知，使用 Microsoft YaHei UI / Segoe UI 系统字体优先级，
  在 100%、125%、150% 和 200% 缩放下由 Qt 使用点尺寸重新排版。
- 中栏底部永久显示启动、停止、重启、API、复制地址、打开脚本/目录/日志和重新扫描操作；
  不可用时保留按钮并显示精确原因。
- 复制字段保存完整底层值，窄窗口只省略显示；空值禁用，成功后显示约两秒反馈，并提供上下文菜单。
- 收藏/最近/已验证运行中/后端/文件夹/标签/游戏分组，活动服务与启动历史严格分离。
- 仅以 `cmd.exe /d /s /c call "<script>"`、`shell=False` 启动，工作目录默认为脚本目录。
- 仅停止以 PID、创建时间、可执行路径和命令行验证的托管进程树；不按进程名批量终止。
- 托管端口冲突提供四个固定选择；非托管占用者绝不提供自动终止。
- 仅对唯一、静态端口字面量创建应用数据目录中的临时副本；原脚本保持逐字节不变，并在启动前显示行级 diff。
- 使用 `/v1/models` 或 `/api/tags` 做轻量就绪检查，不代理推理。
- 每次启动创建 UTF-8 日志；API key 在详情、证据和日志中脱敏。
- 退出时可保留服务器，并持久化验证重连所需的进程身份。
- Qt 和 Windows EXE 均使用多尺寸应用图标；帮助菜单提供使用说明、常见问题、
  安全机制与风险提示、DPI 与字体诊断和关于信息。
- 保留可靠的 OneDir 发行包，并提供独立 OneFile 便携版和可选的每用户 Inno Setup 安装器。
- 可缩放设置窗口包含常规、启动、日志、存储与清理、外观、功能扩展；显示 LocalAppData 的数据库、
  日志、历史和临时文件占用。
- 日志默认保留 30 天、最多 200 MB 和 100 个文件，超过限制时按最旧优先清理，
  且永不删除当前活动启动日志；所有限制均可设为不限。
- 默认以 Windows 无控制台模式后台启动并捕获输出，也可全局或按脚本显示原始控制台；
  `pause`、`set /p`、`choice` 在后台会触发不可绕过的交互警告。
- API readiness 自动检查实际运行端口，依次支持 `/v1/models`、兼容 `/health`
  和 Ollama `/api/tags`，记录 URL、HTTP 状态、错误、时间及重试次数。
- 终端式日志查看器支持 ANSI 清理、严重级别配色、URL 点击、搜索、筛选、暂停画面、
  自动滚动、跳到错误和完整原文复制。
- “打开脚本”可选择 Windows 默认关联，或选择经过存在性验证的编辑器 EXE；
  不提供自由命令输入框。
- 运行日志拥有独立字体、8–24 pt 字号和行距，支持 Ctrl+滚轮、Ctrl+0 与 A−/A+，
  不影响主界面字体。
- 服务器命令后的无条件尾部 `pause` 在信任后不再重复确认；启动前 `pause`、
  `set /p`、`choice` 仍属于真实交互并强制警告。
- 临时端口在可用性检查后自动生成并验证安全副本，查看完整差异改为可选操作。
- 活动表独立显示进程生命周期和 API readiness；动作栏使用克制的绿色启动、
  红色停止、琥珀色重启和蓝色 API 重查提示。
- 可选模型库使用独立 `model_library.sqlite`，只在启用后首次打开标签页时延迟初始化。
  不会启动时扫描、周期扫描或监视目录；只扫描用户明确添加的目录。
- GGUF 读取器只顺序读取有上限的头、元数据和 tensor 描述符，不读 tensor 数据、不加载模型、
  不内存映射完整文件，也不执行完整文件哈希。未变化文件不会重新打开。
- 模型启动、运行、停止或可能分离运行时，模型扫描默认被阻止或在安全文件边界取消。
  模型库不代理推理、监控请求、计算生成速度或改变模型进程优先级。

llama.cpp 的 `-ngl`、`--gpu-layers` 和 `--n-gpu-layers` 支持空格或等号写法，
值可为整数、`auto`（界面显示“自动”）或 `all`（界面显示“全部”）。原始参数写法
保留在解析证据中。

## 解析、可运行性和运行状态

LLMBatDesk 分别显示三个互不替代的概念：

- **解析状态**：脚本能否被静态完整理解。
- **可运行性状态**：脚本明确引用的可执行文件和模型文件在当前电脑上是否存在。
- **运行状态**：当前是否存在通过 PID、创建时间、可执行路径、命令行、进程关系和端口归属验证的服务器。

从另一台电脑复制来的 BAT/CMD 即使引用不存在的 llama.cpp、Ollama 或 GGUF，也仍会正常
进入脚本库并显示解析结果。明确缺少可执行文件或模型时，“启动”按钮默认禁用，并显示各自
的缺失路径。缺失文件不是运行状态，也绝不会让脚本出现在活动服务表。

SQLite 中的旧启动记录在程序启动时全部视为不可信。只有实际服务器身份以及（端口已知时）
属于该服务器的监听 PID 均通过验证时才会重新附加。单独存在的 `cmd.exe`、旧 PID、旧
`STARTING` 状态或配置端口都不能证明模型服务器正在运行。未通过验证的记录进入启动历史，
不会出现在活动表。

## 同端口冲突

启动服务层会在创建 `cmd.exe` 之前再次检查实际目标端口，即使脚本总体只能部分解析，只要
端口来源可信就不会跳过检查。已验证的托管占用提供四个选择：停止并启动目标、仅停止、
使用临时端口、取消。非托管占用只允许选择替代端口、查看进程信息或取消，不提供自动终止。

临时端口使用应用数据目录中的安全副本，只替换唯一、已验证的端口 token/赋值；原脚本保持
逐字节不变。界面会显示行级差异，运行详情、复制地址及 API 检查使用实际端口。

要求 Windows 和 Python 3.12。GUI 依赖 PySide6，不再使用或打包 Tkinter：


## 可选模型库

在“设置 → 功能扩展”启用后，主窗口显示“模型库”标签页。扩展对新旧安装均默认关闭。
禁用时不会导入模型库页面、打开独立数据库、创建扫描工作线程、枚举目录或打开 GGUF。
启用但未打开标签页时同样不会初始化数据库；首次打开只读取缓存和扫描根配置，不会自动扫描。

扫描根必须由用户明确选择，不能是整个驱动器，默认不跟随符号链接、联接点、挂载点或其他
重解析点。扫描是手动、单工作线程、逐文件的；取消在当前受限元数据读取完成后的安全边界生效。

增量身份为规范路径、文件大小和最高可用精度的修改时间。未变化文件直接使用缓存。缺失文件
保留标签和备注并标为缺失。重复提示仅依据大小、名称、架构、参数规模和量化信息，明确标为
“疑似重复”，不代表精确一致。

读取器面向常见 GGUF v2/v3，仅提取受支持的 `general.*`、tokenizer 摘要、架构上下文、
tensor 数量以及由维度计算的估计参数数量。大型 tokenizer token、分数、类型和 merge 数组
会逐项校验或按定宽范围跳过，不会构造完整 Python 列表。字段保留“元数据 / 计算 /
文件名推断 / 未知”来源；损坏、截断、安全限制、版本不支持和 I/O 失败分别显示。

1.3.1 中，扫描目录新增/删除和启用/递归切换会立即更新表格，但添加目录仍不会自动扫描。
模型、扫描目录和引用脚本三张表均可自由调整列宽，并在页面关闭时保存。脚本引用按主模型、
多模态投影、草稿模型、适配器和控制文件区分；同一命令中的主模型与 mmproj 不再被误报为
多个主模型候选。量化显示使用可维护的 `general.file_type` 映射，未来未知值保留原编号。

1.3.2 为模型元数据缓存增加读取器/展示模式版本。升级读取器后，旧缓存只会在用户下一次
明确手动扫描时重读；打开程序或模型库页面不会触发扫描。当前版本的成功、损坏、截断和
不支持版本结果继续使用缓存，I/O/中断类瞬态结果会在下次手动扫描重试。迁移保留扫描根、
标签、备注和脚本引用。

模型表默认隐藏 mmproj、MTP/草稿、LoRA、控制文件和其他附属 GGUF，可通过“显示附属
GGUF”查看。主模型详情列出同一脚本明确关联的组件；一个组件可以同时服务多个主模型。
表格显示友好系列名、标称模型规模和当前 llama.cpp `general.file_type` 名称，原始架构、
精确总参数、原始 file_type、tensor 数和来源仍保留在详情中。

1.3.3 为附属 GGUF 增加非纯颜色的角色标记和主题语义色；主模型仍保持普通行样式。
“关联组件”在为空时折叠表格，选择附属文件时则反向显示所有关联主模型。扫描期间的
“停止扫描”使用明确的停止状态，取消请求后显示“正在停止……”。全局
“重新扫描脚本库”位于脚本库顶部，不再混入选中脚本动作栏。启动历史关闭蓝色交替行，
仅真正选中的行使用选择色。

1.3.4 在选中脚本底部动作栏增加“移除脚本”。单独添加的脚本可只取消注册；目录扫描
发现的脚本可保存为精确路径忽略记录。可选的文件操作仅调用 Windows 回收站，不提供永久
删除后备方案。任何启动中、运行中、停止中、分离未验证或仍有启动预留的脚本都不能移除。
“文件 → 管理已忽略脚本”可取消忽略或清理已不存在的记录；这些操作不会执行脚本。

索引、根目录、标签和备注位于
`%LOCALAPPDATA%\LLMBatDesk\model_library.sqlite`。其损坏只会隔离并重建模型库数据库，
不会替换核心 `llmbatdesk.db`。关闭功能不会删除已有索引或用户备注。

## 用户数据

默认位置是 `%LOCALAPPDATA%\LLMBatDesk\`：

- `settings.json`：根目录、排除项、编辑器和运行时偏好。
- `model_library.sqlite`：可选、可重建的 GGUF 索引、扫描根、标签、备注和脚本引用摘要。
- `llmbatdesk.db`：非技术元数据、信任哈希、操作历史和托管启动身份。
- `logs\`：每次启动的 UTF-8 日志。
- `temporary\`：临时端口覆盖副本。

删除 OneFile 便携 EXE 不会删除上述目录，因为程序文件与持久用户数据有意分离。使用
“文件 → 设置 → 存储与清理”可以打开目录、查看占用、清理各类数据，或在准确输入
“删除全部数据”后删除全部用户数据。存在活动或正在启动的服务时会拒绝全部删除。

自动清理在应用启动、启动日志结束以及用户请求时于工作线程运行。默认限制为 30 天、
200 MB、100 个文件；超过任何限制都从最旧日志开始删除，活动日志始终受保护。

## API readiness 与启动方式

“端口监听中，API 未就绪”表示进程、端口及监听 PID 已验证，但 API 请求尚未成功。详情会
区分检查中、认证要求、404 不兼容、请求超时和进程退出，并显示实际检查 URL、HTTP 状态、
错误、时间和重试次数。检查使用实际运行端口，因此临时端口不会继续探测配置端口。

默认“后台启动，不显示控制台”使用 `CREATE_NO_WINDOW`、隐藏 startup info 和
`shell=False`，同时保留 stdout/stderr 捕获与进程树管理。“显示原始控制台窗口”使用新的
Windows 控制台，日志捕获可能受脚本行为限制。每个脚本可在元数据中覆盖全局方式。

启动确认可设为每次、首次或内容变化后、以及跳过已信任未变化脚本。信任绑定内容哈希和
工作目录。端口冲突、临时端口、内容/工作目录变化、部分解析、可疑路径和后台交互脚本仍会
强制确认。

服务器命令后的无条件尾部 `pause` 通常只用于服务器退出后保留手动控制台窗口，不会在
内容和工作目录未变化时永久触发确认。服务器启动前的 `pause`、`set /p`、`choice` 或
无法确定的分支交互仍会强制确认。确认窗口会列出本次原因，并说明勾选“不再询问”后仍会
生效的安全规则。

“设置 → 常规”可选择 Windows 注册的默认编辑关联（使用安全的 `edit` 动词，不执行脚本），
或通过“浏览……”选择 Notepad、
Notepad++、VS Code 等实际存在的编辑器 EXE。路径只读显示，不接受命令参数，也不会与

## 运行状态与 API 状态

活动表的“状态”只描述进程生命周期，例如正在启动、运行中、正在停止或启动失败；
“API”单独显示未检查、检查中、端口尚未监听、未就绪、已就绪、认证、404 或超时。
服务成功后显示“状态：运行中 / API：API 已就绪”，不会在两列重复 API 文本。

扫描目录中不会写入元数据。只有用户明确选择“保存托管副本”时才会在用户选择的位置创建新文件，并且永不覆盖原文件。

## 安全模型

解析是静态操作，绝不执行脚本。解析成功不表示 BAT/CMD 安全。每个内容 SHA-256 在第一次启动前必须由用户查看路径、警告和脱敏原文后确认；内容变化会自动使信任失效。

程序没有任意命令输入框。启动层只接受存在的 `.bat` / `.cmd` 路径。停止层拒绝身份不匹配或 PID 被复用的进程。非托管端口占用者只显示信息，绝不自动终止。

API key 不进入元数据数据库；普通详情和日志会隐藏值。原文件自身仍包含用户写入的密钥，因此通过外部编辑器打开原文件时当然可见。

## 解析限制

Windows 批处理语言包含运行时分支、子程序、延迟展开、注册表/命令输出、外部 `CALL`、生成文本和任意程序调用。LLMBatDesk 不声称兼容任意 BAT 语法。遇到这些结构时会标记“部分解析”或“未知或动态”，列出无法静态确定的字段和原因，并禁用不安全的端口覆盖。

版本 1 不支持 PowerShell 脚本，不做完整 LM Studio 适配，不推断 `ollama serve` 会加载哪个模型，也不监控高频 GPU 指标。

使用 `START`、复杂分离或启动后立即重设父子关系的脚本，可能无法在短启动窗口内取得充分
所有权证据。这类记录会显示为失败或“分离/无法验证”，而不会冒险显示为活动服务或允许停止。
